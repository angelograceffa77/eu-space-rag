One command to collect, archive, build, check and publish:
node .\daily\daily.cjs --publish

The daily controller runs the registered procurement collectors with three workers.
Where supported, it requests the latest 14 days. TED also retains its separate
search for still-open notices. Existing historical evidence is retained in the
master; this daily command does not claim a new complete historical crawl.

A run interrupted before completion resumes its recorded job selection. Do not
delete checkpoints or start a second collector manually in the same run folder.
Austria and Estonia receive one bounded checkpoint retry after a failed attempt.
The default job limit is 45 minutes; Czechia has a 90-minute allowance following
the first live run. A longer allowance does not imply complete source coverage.
An active-run lock prevents two daily runs from overlapping. A held run requires
review of its error; the last validated published snapshot remains available.

Status is stored in daily\state.json. Collector logs and original outputs are in
.procurement-runs\daily-<timestamp>\collectors. Each collector's run-state.json
records its assessment. Valid output is not proof of complete source coverage.

Before building, original run evidence is copied and checksum-verified under:
C:\Users\angel\OneDrive\Desktop\knowledge\03_PROCUREMENT\Procurement Data
The original relative folder structure is preserved. Audit receipts are in
_audit. Source files are not rewritten or deleted by the daily controller.

The master retains original source records alongside normalized procurement,
lot and company-match records. Missing observations never imply closure.
Previously open tenders without a fresh observation are marked stale/unverified.
Company matches are suggestions backed by evidence, not eligibility assurances.

Publication is held if fewer than half of jobs produce accepted nonempty data,
source-record counts fall, malformed records increase, required validation fails,
or procurement counts change beyond the configured review limits.
Partial source coverage remains explicit even when publication passes.
When a country export contains a successful current source and a failed archive,
only records attributed to the successful source can count as fresh. The failed
source remains visible and its records are retained only as unverified evidence.
Every previous original record must survive with the identical text checksum.
Newly retrieved older notices cannot override later awards or cancellations.
Publication stops if GitHub contains a different master than the expected baseline.
Newly collected records whose original timestamp is fixed at noon are recognized
through their existing raw files inside the current run, without rewriting dates.

GitHub receives only the authoritative Procurement-Master package on main:
03_PROCUREMENT/Procurement Data/Procurement-Master/manifest.json
03_PROCUREMENT/Procurement Data/Procurement-Master/current/...
Start retrieval with manifest.json, then follow its data and index manifests.
Data parts are authoritative; index files aid discovery. Do not ingest both as
duplicate substantive records, or combine this master with older source exports.

The publisher uses an isolated Git repository under the external archive's
_publication folder. It preserves every remote path outside Procurement-Master,
does not stage local unrelated work, and never force-pushes. The normal checkout's
branch/index are not advanced by this isolated publication. Do not reset local
work just because its branch is behind the newly published remote commit.

Publication receipts, uploaded-file hashes and commit IDs are retained in
_publication\runs; _publication\latest.json records the latest verified push.

The scheduled local automation requires the computer and Codex app to be running.
A manual successful run and the first scheduled run are separate verification
steps. Consult the Phase 7 status report for which have actually completed.

The published current/manifest.json uses small metadata catalogs. Follow
 data.partsCatalog.parts to read the complete list of authoritative data parts,
 and index.partsCatalog.parts for lookup parts. Each referenced file is a JSON
 array with a recorded SHA-256 checksum. current/inputs.json similarly lists
 catalogs of preserved input metadata. The local full manifest remains intact.
The supplied master reader and verifier support both layouts.

National daily collection keeps the 2020 onward date scope: an older publication
can still be open today. TED uses a recent-notice window plus its separate all-open
deadline search. The first scheduled run will verify the final national scope
policy live; the initial manual run used the narrower recent-notice window.
