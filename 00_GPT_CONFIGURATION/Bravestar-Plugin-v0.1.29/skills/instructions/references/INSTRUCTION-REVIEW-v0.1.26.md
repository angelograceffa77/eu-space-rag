# v0.1.26 instruction cleanup

The 78 command names, descriptions, specialist ownership, templates, individual profiles, source references and checksums are preserved. Command routing now includes stable IDs for selection controls.

## Where each rule lives
- Orchestrator: identity, onboarding, intake, research, dataset routing, evidence, specialist responsibilities and chat disclosure.
- COMMAND-SELECTION.md: clickable menus, natural-language choices, paging, descriptions and honest fallback when the host lacks controls.
- Specialist skills: subject-specific methods, commands and findings; shared handover rules link back to the orchestrator.
- REPORT-FORMATS.md: Executive Standard versus Detailed Report, page targets and writing style.
- REPORT-STANDARD.md: layout, logo, five sections, source presentation, disclaimer, contact and official-form separation.
- REPORT-SPECIFIC-PRACTICE.md: individual profiles, benchmark use and template maintenance.
- RELEASE-CHECKLIST.md: content/presentation checks, scripts, recorded review, manual fallback and hold conditions.
- ARCHIVE-AND-DELIVERY.md: sending authority, receipts, retry handling, archive folders and protected retention.

## Clarifications
- Confidence belongs in chat/private evidence, not generated reports. Supported risk severity is a different concept.
- Automatic checks are used when available. Manual fallback must check and record the same requirements; inability to finish required checks means draft/hold, not a waived requirement.
- Official application forms and contract clauses keep their required layout. The accompanying Bravestar report keeps its five sections.
- Capability website evidence follows the 90-day rule; this does not erase historical award evidence.
- A menu click does not authorise sending or other external actions. Clear natural language does not trigger a redundant menu.

## Validation scope
Checked command preservation, unchanged individual templates/profiles and validators, protected safeguards, JSON, skill syntax and linked paths. Host UI interaction was not live-tested; instructions cannot add controls to unsupported hosts. This is an editorial consistency review, not a formal proof that every future response will comply.
